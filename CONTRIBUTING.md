# Contributing

Thanks for helping. This is the default guide for GBOGEB repositories that don't have their own `CONTRIBUTING.md`; a repository's own guide always wins.

## Before you start

- Search open issues and pull requests first, so the same work isn't done twice.
- For anything larger than a small fix, open an issue first and agree the approach.

## Making a change

1. Fork the repository, or create a branch if you have write access.
2. Keep each pull request to one change, and say in its description what it changes and how you checked it.
3. Run the repository's tests and linters locally on the Python version it declares (`.python-version` or the CI matrix).
4. Don't merge, or ask for a merge, while any required check is red.
